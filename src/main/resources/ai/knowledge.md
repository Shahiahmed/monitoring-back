# База знаний системы SARAP

Формат: раздел начинается с "## Заголовок", далее строка "keywords: ..." со словами
для поиска, далее текст. Текст попадает в промпт ассистента как справка — пиши
короткими фактами, без воды. Ключевые слова указывай в виде основы слова
("инцидент", "доступност"), чтобы совпадали любые падежи.

## О системе
keywords: sarap, сарап, система, что это, чем занимается, назначение, мтзсн, кто ты, умеешь
SARAP — корпоративная система мониторинга и аналитики для МТЗСН РК (Министерство труда
и социальной защиты населения Республики Казахстан).
Система решает четыре задачи:
1. Учёт событий — плановые и внеплановые работы, инциденты, тревоги PRTG.
2. Расчёт доступности информационных систем (ИС) МТЗСН.
3. Мониторинг боевых серверов — CPU, ОЗУ, диск по SSH.
4. Контроль сервисов, сертификатов ЭЦП/SSL и действий пользователей.
Интерфейс двуязычный: русский и қазақша. Есть светлая и тёмная тема.

## Разделы системы
keywords: раздел, меню, навигац, где найти, где посмотреть, страниц, вкладк, перейти
Меню слева содержит разделы:
- Главная — сводка и графики за год.
- Мониторинг серверов — метрики боевых серверов.
- Инциденты: Журнал событий, Статистика, Доступность ИС.
- Сервисы: Список сервисов, Реестр сервисов, Добавить сервис.
- Справочники: Местоположения, Окружения, Гос органы, ИС, Типы взаимодействия,
  Типы приложения, Типы инцидентов, Серверы.
- Пользователи: Список пользователей, Регистрация, Роли.
- Настройки: ЭЦП / SSL, Журнал действий.
Сверху в шапке: логотип (возврат на главную), сроки сертификатов ЭЦП и SSL,
переключатель языка, переключатель темы, вход в профиль.
Меню сворачивается до иконок кнопкой на границе меню и содержимого.

## Роли и права доступа
keywords: роли, ролев, права, права доступ, кому доступ, админ, admin, кто может, разрешен, запрещ, суперадмин
В системе три роли:
- USER — просмотр разделов, без изменения данных.
- ADMIN — всё что USER, плюс ведение событий (работы, инциденты, тревоги PRTG),
  регистрация пользователей, справочники, настройки.
- SUPER_ADMIN — полный доступ: удаление пользователей, смена чужих паролей.
Разделы «Пользователи» и «Настройки» видны только ADMIN и SUPER_ADMIN.
Вкладка «Тревоги PRTG» в журнале событий тоже видна только ADMIN и SUPER_ADMIN.

## Главная панель
keywords: главн, дашборд, панел, сводк, график, стартов
Главная страница показывает сводку за текущий год: количество инцидентов,
количество работ, суммарный простой по инцидентам и среднюю доступность по ИС МТЗСН.
Ниже два графика — активность событий и распределение простоев.
Год в подзаголовке — текущий календарный год.

## Три типа событий: работы, инциденты, тревоги PRTG
keywords: работ, инцидент, prtg, тревог, различ, разниц, отлича, тип событ, что такое
Это ТРИ разные сущности, они хранятся раздельно и не смешиваются:
- Работы — плановые и внеплановые работы. Тип берётся из справочника и имеет ровно
  два значения: «Плановые работы» и «Внеплановые работы».
- Инциденты — сбои и отказы. Только они участвуют в расчёте доступности ИС.
- Тревоги PRTG — сигналы системы мониторинга PRTG. Внутренняя сущность, доступна
  только ADMIN и SUPER_ADMIN.
Работу или инцидент можно создать на основе тревоги PRTG: в форме сверху есть
«Загрузить из тревоги PRTG». При этом создаётся НОВАЯ запись, сама тревога не меняется,
а в карточке появляется отметка «Создано на основе тревоги PRTG №N».

## Журнал событий
keywords: журнал событ, событ, список инцидент, таблиц, фильтр, экспорт, xlsx, найти запис
Раздел «Инциденты → Журнал событий» — основная рабочая таблица. Три вкладки:
Работы, Инциденты, Тревоги PRTG. Каждая вкладка читает свои данные.
Возможности: фильтры по типу, по ИС МТЗСН, по статусу и по датам; чипы годов;
экспорт в XLSX; создание записи кнопкой «Новое событие»; редактирование и удаление.
Записи с несколькими периодами простоя хранят их как интервалы — у одной записи
может быть несколько интервалов «начало — окончание».

## Как добавить или изменить событие
keywords: добав, создат, завест, внест, редактир, изменит, удалит, новое событ, как офор
Добавление доступно ролям ADMIN и SUPER_ADMIN.
Путь: Инциденты → Журнал событий → нужная вкладка → «Новое событие».
Формы разные для каждого типа:
- Работы: тип работы, номер письма, примечание, ИС МТЗСН, интервалы дат.
- Инцидент: тип инцидента, акт сбоя, входящее и исходящее письмо, причина, примечание,
  флажки «Зафиксировано в АО НИТ», «Без времени простоя», «Учитывать в % доступности»,
  ИС МТЗСН, интервалы дат.
- Тревога PRTG: данные тревоги системы мониторинга.
К записи можно приложить файлы. Редактирование открывается той же формой из журнала.

## Расчёт доступности ИС
keywords: доступност, процент, availability, формул, посчит, расчет, простой, sla, 99
Раздел «Инциденты → Доступность ИС».
Доступность одной ИС = 100 × (1 − простой в минутах / минут в году).
Минут в году = 1440 × 365, в високосном году 1440 × 366.
Общая доступность = (минут_в_году × N − суммарный простой) / (минут_в_году × N) × 100,
где N — количество учитываемых ИС.
Простой попадает в расчёт ТОЛЬКО если выполнены все три условия:
1. У инцидента включён флажок «Учитывать в % доступности».
2. У инцидента НЕ включён флажок «Без времени простоя».
3. У информационной системы в справочнике включён учёт в доступности.
Работы и тревоги PRTG в доступность не входят — только инциденты.

## Статистика событий
keywords: статистик, отчет, диаграмм, по месяц, по типам, сколько за
Раздел «Инциденты → Статистика». Показывает разрезы: по типам (количество и часы
простоя), по месяцам (количество и часы простоя), по ИС (количество сбоев и время простоя).
Фильтры: год, квартал, произвольный период «дата с — дата по».

## Как считается период при фильтрации
keywords: период, дата, фильтр по дат, год, квартал, когда учит, попада, за какой
Фильтрация по датам во всех журналах и отчётах идёт по дате ИНТЕРВАЛА события,
а не по дате создания записи. Запись, созданную сегодня, но с интервалом за прошлый год,
система отнесёт к прошлому году. Чипы годов тоже строятся по датам интервалов.

## Мониторинг серверов
keywords: сервер, cpu, озу, память, ram, диск, метрик, нагрузк, ssh, хост, аптайм, онлайн
Раздел «Мониторинг серверов» показывает боевые серверы из реестра. Метрики снимаются
по SSH: загрузка CPU в процентах, ОЗУ занято и свободно в ГБ и процентах, заполнение диска
в процентах, аптайм, статус онлайн или оффлайн.
Есть кнопка обновления метрик, график сравнения серверов по ресурсам и переход
к подробностям по клику на сервер. Если сервер недоступен по SSH, он отмечается как
оффлайн и метрик по нему нет.

## Сервисы
keywords: сервис, приложен, деплой, развертыв, лог, окружен, статус сервис, реестр
«Сервисы → Список сервисов» — приложения и их развёртывания по окружениям, статус каждого
развёртывания, ссылки на URL, просмотр логов в реальном времени с фильтром grep.
«Сервисы → Реестр сервисов» — карточки приложений, поиск, удаление.
«Сервисы → Добавить сервис» — регистрация нового приложения (ADMIN и выше).

## Справочники
keywords: справочник, справоч, местополож, окружен, гос орган, типы взаимод, типы приложен, типы инцидент, добавить ис
Раздел «Справочники» хранит списки, которые подставляются в формы:
Местоположения, Окружения, Гос органы, Информационные системы (ИС), Типы взаимодействия,
Типы приложения, Типы инцидентов, Серверы.
В справочнике ИС у каждой системы есть признак «учитывать в доступности» — он влияет
на расчёт процента доступности. Изменение справочников доступно ADMIN и SUPER_ADMIN.

## Пользователи
keywords: пользовател, учетн, аккаунт, регистрац, сотрудник, добавить пользоват, деактив
«Пользователи → Список пользователей» — все учётные записи.
«Пользователи → Регистрация» — создание учётной записи, доступно ADMIN и SUPER_ADMIN.
«Пользователи → Роли» — справочник ролей.
Удаление пользователей и смена чужого пароля — только SUPER_ADMIN.

## Сертификаты ЭЦП и SSL
keywords: сертификат, эцп, ssl, срок, истека, продлит, безопасн
Раздел «Настройки → ЭЦП / SSL» ведёт учёт сертификатов и сроков их действия.
Ближайшие сроки продублированы в шапке системы на каждой странице: если до истечения
осталось мало дней, это видно сразу при входе.

## Журнал действий
keywords: журнал действ, аудит, кто изменил, истори действ, лог действ, активност
Раздел «Настройки → Журнал действий» фиксирует действия пользователей: вход, регистрация,
удаление пользователя, создание, изменение и удаление записей, изменение профиля,
активация и деактивация. Есть поиск по email и описанию и фильтр по типу действия.

## Профиль, тема, язык и обучение
keywords: профил, парол, смена парол, аватар, тема, темн, светл, язык, казах, обучен, тур, инструкц
Профиль открывается иконкой пользователя в шапке. Там меняются фото, личные данные
и собственный пароль. Требования к паролю: минимум 8 символов, заглавная буква,
строчная буква и цифра.
Тема и язык переключаются в шапке, выбор запоминается в браузере.
В профиле есть кнопка «Пройти обучение заново» — она запускает интерактивный тур
по интерфейсу, который показывается автоматически при первом входе.

## Вход в систему
keywords: вход, войти, логин, забыл парол, восстанов, не могу зайти, авториз, выйти
Вход по email и паролю на странице входа. Если пароль забыт — ссылка восстановления
на той же странице. Сессия хранится в браузере; кнопка «Выйти» находится внизу
левого меню. Если учётная запись деактивирована, вход невозможен — нужно обратиться
к администратору.

## Что умеет ассистент
keywords: умеешь, можешь, помощ, что спросить, ассистент, помощник, чат-бот
Ассистент отвечает по этой справке и по двум источникам живых данных:
- статистика инцидентов и доступности за год или квартал;
- текущие метрики серверов (CPU, ОЗУ, диск), в том числе с условиями
  вида «серверы, где свободно меньше 4 ГБ».
Живого доступа к спискам пользователей, сервисов, сертификатов, журналу действий
и содержимому справочников у ассистента НЕТ. Такие вопросы нужно смотреть
в соответствующем разделе интерфейса — ассистент подскажет, в каком именно,
но не назовёт конкретные записи и числа оттуда.
